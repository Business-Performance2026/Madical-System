# عيادتي - نظام حجز مواعيد العيادات

نظام ويب بسيط لحجز مواعيد العيادات، يخدم ثلاثة أنواع مستخدمين: **المريض**، **العيادة**، و**الأدمن**.

## أنواع المستخدمين

**1. المريض**
- إنشاء حساب، البحث عن العيادات، حجز موعد، متابعة حالة الحجز، عرض المواعيد القادمة/السابقة

**2. العيادة**
- تسجيل حساب (يتطلب موافقة الأدمن)، إضافة أطباء وأوقات عمل، قبول/رفض طلبات الحجز، جدول المواعيد

**3. الأدمن**
- الموافقة على تسجيل العيادات، إدارة جميع الحسابات، إيقاف أو حذف أي حساب، لوحة إحصائيات

## القرارات التقنية

| القرار | الاختيار |
|---|---|
| نوع المشروع | موقع ويب بسيط (HTML / CSS / JS) |
| قاعدة البيانات والمصادقة | Firebase (Authentication + Firestore) - مشروع madical-system |
| طريقة تحميل Firebase SDK | Compat SDK عبر `<script>` من CDN |
| الاستضافة | GitHub / GitHub Pages |
| اتجاه الصفحة | RTL / عربي |
| الخط | Tajawal |

## ما تم إنجازه حتى الآن

### 1. `index.html` - نقطة الدخول
- تسجيل دخول / إنشاء حساب (مريض أو عيادة)
- عند التسجيل يُنشأ مستند بمجموعة `users`: `name`, `email`, `role`, `status`, `createdAt`
- حساب العيادة يُنشأ بحالة `pending` تلقائياً
- توجيه تلقائي بعد الدخول حسب `role`: مريض → `patient/home.html` | عيادة → `clinic/dashboard.html` | أدمن → `admin/dashboard.html`

### 2. `admin/dashboard.html` - لوحة الأدمن
- **حماية الصفحة**: يتحقق إن المستخدم مسجّل دخول وحسابه `role: admin` و `status: active`، وإلا يرجّعه لصفحة الدخول
- **إحصائيات**: عدد العيادات الفعّالة، الأطباء (0 مؤقتاً)، المرضى، الحجوزات (0 مؤقتاً)
- **طلبات تسجيل العيادات المعلّقة**: قبول (`status → active`) أو رفض (`status → rejected`)
- **آخر التسجيلات**: أحدث 5 حسابات
- **إدارة الحسابات**: جدول لكل المستخدمين (فلترة عيادات/مرضى) مع أزرار إيقاف/تفعيل/حذف

**ملاحظة مهمة**: زر "حذف" يحذف بيانات المستخدم من Firestore فقط (يمنعه من استخدام التطبيق)، لكن لا يحذف حساب الدخول (Authentication) نفسه لأن هذا يتطلب صلاحيات إدارية (Admin SDK / Cloud Function) غير متاحة من المتصفح مباشرة. لو احتجنا حذف كامل لاحقاً، لازم نضيف Cloud Function.

### كيفية إنشاء أول حساب أدمن
لا يوجد تسجيل أدمن من الواجهة (مقصود لأسباب أمان). يُنشأ يدوياً:
1. Firebase Console → Authentication → Add user (بريد + كلمة مرور)
2. انسخ الـ UID
3. Firestore → مجموعة `users` → مستند جديد بنفس الـ UID، بالحقول: `name`, `email`, `role: "admin"`, `status: "active"`, `createdAt`

## قبل التجربة - إعدادات مطلوبة على Firebase Console
1. **Authentication** → Sign-in method → تفعيل Email/Password
2. **Firestore Database** → إنشاء قاعدة بيانات (Test mode مؤقتاً)

### 3. `clinic/dashboard.html` - لوحة العيادة
- **حماية الصفحة**: يتحقق إن `role: clinic` و `status: active`
- **إحصائيات**: حجوزات اليوم، حجوزات قادمة، طلبات جديدة، إجمالي المرضى
- **طلبات الحجز**: قبول (`status → accepted`) أو رفض (`status → rejected`)
- **إدارة الأطباء**: إضافة طبيب (اسم + تخصص)، تحديد أوقات العمل (يوم + من - إلى)، حذف طبيب أو وقت عمل
- **الجدول الأسبوعي**: يعرض المواعيد المؤكدة فقط (الأحد - السبت)
- **بحث المرضى**: فلترة فورية على أسماء المرضى اللي حجزوا مع هذي العيادة

### هيكل بيانات Firestore الجديد

**مجموعة `doctors`**
| الحقل | الوصف |
|---|---|
| `clinicId` | UID تبع العيادة المالكة |
| `name`, `specialty` | اسم وتخصص الطبيب |
| `workingHours` | مصفوفة `{ day, start, end }` |
| `createdAt` | تاريخ الإضافة |

**مجموعة `bookings`**
| الحقل | الوصف |
|---|---|
| `clinicId`, `doctorId`, `doctorName` | مرجع العيادة والطبيب |
| `patientId`, `patientName` | مرجع المريض |
| `date` (`YYYY-MM-DD`), `time` (`HH:MM`) | موعد الحجز |
| `status` | `pending` / `accepted` / `rejected` |
| `createdAt` | تاريخ إرسال الطلب |

**آلية قفل الوقت**: أي وقت صار له حجز بحالة `accepted` لازم صفحة المريض (الخطوة الجاية) تستثنيه من الأوقات المتاحة عند نفس الطبيب بنفس التاريخ — هذا هو نظام القفل التلقائي المذكور بالفكرة الأساسية.

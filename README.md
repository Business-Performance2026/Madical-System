# موعد - نظام حجز مواعيد العيادات

نظام ويب بسيط لحجز مواعيد العيادات، يخدم ثلاثة أنواع مستخدمين: **المريض**، **العيادة**، و**الأدمن**.

## أنواع المستخدمين

**1. المريض** — إنشاء حساب، اختيار عيادة ثم طبيب ثم وقت متاح فعلياً، إرسال طلب حجز، متابعة حالته، عرض المواعيد القادمة/السابقة

**2. العيادة** — تسجيل حساب (يتطلب موافقة الأدمن)، إضافة أطباء وتحديد أوقات عملهم، قبول/رفض طلبات الحجز، جدول أسبوعي، بحث المرضى

**3. الأدمن** — الموافقة على تسجيل العيادات، إدارة جميع الحسابات، إيقاف أو حذف أي حساب، لوحة إحصائيات

## الهوية البصرية

- **الاسم**: موعد (Mawid)
- **الشعار**: `assets/logo.jpg` — شعار حقيقي (تقويم + ساعة + يد + علامة طبية)
- **الألوان**: خلفية التطبيق كحلية غامقة `#05314D` + كحلي `#044059` (نصوص وعناوين فوق البطاقات البيضاء) + **ذهبي `#D19F00` كلون مميز ثانوي** (الأزرار الرئيسية، التبويبات النشطة، فلتر التخصص المختار، لافتة الحجز بالرئيسية)
- **قاعدة التصميم**: خلفية كحلية + بطاقات بيضاء فوقها (لضمان وضوح القراءة بالجداول والنماذج الكثيفة) + الذهبي محجوز للعناصر "النشطة/الأساسية" بس (نظام إشارات بصري متسق: كل ما شفت ذهبي = هذا الزر/التبويب الأساسي أو المختار حالياً)
- الأزرار الرئيسية بتدرج لوني متحرك (ذهبي ↔ كحلي)، مع حركات "رفع" خفيفة عند التمرير على البطاقات لإحساس أكثر حيوية
- **عناوين الأقسام بلوحات التحكم** (فوق بطاقات بيضاء) بمستطيل كحلي وكتابة بيضاء؛ **عنوان دليل العيادات بالرئيسية** (فوق الخلفية الكحلية مباشرة) بمستطيل ذهبي بدل الكحلي، عشان يبرز
- **تحسينات للهاتف (شاملة)**: على شاشات أقل من 480px — أزرار تسجيل الدخول/الخروج والجرس أصغر، عناوين اللوحات ("لوحة العيادة"/"لوحة الأدمن") أصغر، الجداول (الطلبات، المرفوضة، الجدول الأسبوعي، حسابات الأدمن) بخط وحشو أضيق، بطاقات العيادات/التخصصات بعمودين، بطاقات الأطباء بعمود واحد، والنماذج المصغّرة (إضافة طبيب/وقت/تعديل) تصير عمودية بدل صف مزدحم

## ما تم إنجازه حتى الآن

### 1. `index.html` - دليل العيادات (الشاشة الرئيسية العامة)
أعيد تصميمها بالكامل لتكون **دليل عيادات حي** بدل صفحة تسويقية عامة — يشوفها أي زائر بدون تسجيل دخول:

- **هيرو مضغوط**: بحث واحد بس، بدون كلام تسويقي زايد + سطر إحصائيات حي ("X عيادة • Y طبيب • Z تخصص")
- **شريط فلاتر التخصصات**: كل تخصص (أسنان، جلدية...) يعرض **عدد العيادات المتوفرة له فعلياً** بجانبه، ويفلتر النتائج فوراً بنفس الصفحة
- **دليل العيادات نفسه صار محور الصفحة** (مو قسم صغير بالأسفل): بطاقات مصممة لكل عيادة (أفتار بأول حرف من الاسم بلون مميز، اسم العيادة، عدد الأطباء، وسوم التخصصات المتوفرة)
- **البحث وفلتر التخصص يشتغلون مع بعض**: تقدر تكتب كلمة وتختار تخصص بنفس الوقت
- التسجيل/الحجز الفعلي لسا يحتاج حساب (كل بطاقة عيادة تودّي لـ `login.html`)

**ملاحظة أمان مقصودة**: اسم وبريد العيادة، واسم وتخصص كل طبيب، معلومة عامة (زي أي دليل أعمال تجاري) — لكن باقي البيانات (مرضى، حجوزات، أرقام جوال) تبقى محمية بالكامل.

### 2. `login.html` - تسجيل الدخول / إنشاء حساب
نفس محتوى `index.html` القديم، بس انتقل لملف مستقل. فيه رابط "رجوع للرئيسية". **رقم الجوال (واتساب) إجباري الآن لأي حساب جديد — مريض أو عيادة.**

### 3. `admin/dashboard.html` - لوحة الأدمن
- حماية الصفحة (`role: admin` و `status: active`)
- إحصائيات حقيقية: عدد العيادات، الأطباء، المرضى، الحجوزات
- الموافقة/الرفض على طلبات تسجيل العيادات + ✏️ تعديل + 🗑️ حذف لكل طلب
- **قسم "العيادات المرفوضة" منفصل**: نفس إجراءات طلبات التسجيل (قبول لإعادة النظر، رفض، تعديل، حذف)
- آخر التسجيلات (أحدث 5 حسابات)
- إدارة الحسابات: فلترة + ✏️ تعديل (نموذج واحد بكل الحقول: الاسم، البريد، ورقم الجوال) + ✅/⛔ تفعيل/إيقاف + 🗑️ حذف

**ملاحظة مهمة عن التعديل**: زر "تعديل" يغيّر بيانات الملف الشخصي بـ Firestore بس (اللي تظهر بالتطبيق)، **ما يغيّر بريد الدخول الفعلي بـ Firebase Authentication**. يعني لو غيّرت بريد مستخدم من هنا، هو لسا يسجّل دخول بالبريد القديم. تغيير بريد الدخول نفسه يحتاج صلاحيات Admin SDK (Cloud Function) غير متاحة من المتصفح مباشرة.

**ملاحظة**: زر "حذف" يحذف بيانات المستخدم من Firestore فقط، لا يحذف حساب الدخول (Authentication) نفسه — يحتاج Cloud Function لاحقاً لو أردنا حذف كامل.

### 4. `clinic/dashboard.html` - لوحة العيادة
- حماية الصفحة (`role: clinic` و `status: active`)
- إحصائيات: حجوزات اليوم، قادمة، طلبات جديدة، إجمالي المرضى
- قبول/رفض طلبات الحجز (القبول يقفل الوقت تلقائياً)
- **قسم "المواعيد المرفوضة" منفصل**: كل حجز مرفوض يظهر هنا بنفس الأزرار (قبول لإعادة النظر، رفض، ✏️ تعديل، 🗑️ حذف، 💬 واتساب) — ما يختفي بعد الرفض
- **إشعار فوري (Toast) لكل حجز جديد**: البيانات تتحدث لحظياً بدون ما تحتاج تحدّث الصفحة (Firestore real-time listener)، وأي طلب حجز جديد يوصل تطلع له نافذة تنبيه صغيرة بالزاوية تقولك "🔔 حجز جديد وصل" مع اسم المريض وموعده
- **🔔 أيقونة جرس بالهيدر مع شارة عدد حمراء**: تعرض عدد الطلبات "قيد الانتظار" حالياً (تزيد لحظياً مع كل حجز جديد)، وتنقص تلقائياً بمجرد ما تتخذ قرار (قبول أو رفض) — تختفي الشارة تماماً لو وصل العدد صفر
- **لكل حجز (بكل الأقسام)**: زر واتساب دايم موجود، ✏️ تعديل شامل (اسم المريض، جواله، التاريخ، والوقت مع بعض بنموذج واحد — مع نقل قفل الوقت تلقائياً لو تغيّر الموعد)، 🗑️ حذف نهائي
- إدارة الأطباء: إضافة طبيب + ✏️ تعديل شامل (الاسم والتخصص) + **تحديد أوقات العمل بتاريخ محدد فعلي** (مو يوم أسبوع متكرر) + 🗑️ حذف + **🖨️ طباعة/تصدير PDF لجدول الطبيب الأسبوعي**
- **قائمة الأطباء صارت أكورديون قابل للطي** (اسم + تخصص بصف واحد، تفتحه لتشوف التفاصيل) بدل كروت تاخذ مساحة كبيرة
- الجدول الأسبوعي (المواعيد المؤكدة) بنفس أزرار التواصل والتعديل والحذف، مع:
  - **فلاتر حقيقية قابلة للدمج**: اختر طبيب معيّن و/أو تاريخ معيّن و/أو وقت معيّن — تقدر تجمعهم مع بعض (مثلاً: طبيب فلان + الساعة 9 بس). بدون فلتر تاريخ، يعرض هذا الأسبوع بس؛ باختيار تاريخ محدد يبحث بذاك اليوم حتى لو خارج الأسبوع الحالي
  - **🖨️ طباعة/تصدير PDF** لبالضبط النتائج المفلترة الظاهرة قدامك
- **قسم "المواعيد القادمة خلال 24 ساعة" (جديد)**: بجانب جدول الأسبوع مباشرة — يعرض مواعيد اليوم وبكرة مع بعض تلقائياً (يعني أي موعد تاريخه بكرة يظهر بهذي القائمة من اليوم)، عشان تقدر ترسل تذكير مبكر قبل ما ينسى المريض. نفس أزرار جدول الأسبوع بالضبط (💬 واتساب، 🔔 تذكير، ✏️ تعديل، 🗑️ حذف، ❌ لم يحضر لو التاريخ اليوم)
- بحث فوري عن المرضى

**ملاحظة عن الطباعة**: زر الطباعة يفتح نافذة طباعة المتصفح مباشرة — اختر **"Save as PDF" / "حفظ كـ PDF"** من قائمة الطابعات بدل طابعة حقيقية، وبتحصل على ملف PDF. ما يحتاج أي مكتبة خارجية.

**ملاحظة**: تعديل اسم/جوال المريض من داخل الحجز يغيّر بيانات هذا الحجز بس، ما يعدّل حساب المريض نفسه ولا باقي حجوزاته.

### 5. `patient/home.html` - لوحة المريض
- حماية الصفحة (`role: patient` و `status: active`)
- **حجز موعد بـ 3 خطوات:**
  1. اختيار العيادة (بحث بالاسم) — **يعرض تخصصات العيادة تحت اسمها بدل بريدها الإلكتروني**
  2. اختيار الطبيب
  3. **تقويم مخصص** يلوّن أيام دوام الطبيب فعلياً باللون الأخضر (يقدر يضغطها)، والباقي رمادي (غير قابل للضغط) — المريض ما يحتاج "يدور" التاريخ يدوياً، يشوف مباشرة أي أيام متاحة. بعد اختيار يوم، تظهر تلقائياً بس الأوقات المتاحة فيه (مبنية على أوقات عمل الطبيب لذلك اليوم بالضبط، مطروح منها أي وقت له قفل بـ `lockedSlots`) — **لو كل الأوقات محجوزة، تطلع رسالة تحذير واضحة بلون أحمر وخط Bold**
- **نافذة منبثقة (Popup)** تأكيد فور إرسال الحجز، فيها رقم الحجز بخط كبير وواضح
- قسمي **"مواعيدي الحالية"** و **"مواعيدي السابقة"** (بدل "المواعيد القادمة/السابقة")
- قسم "المواعيد القادمة" و"المواعيد السابقة" مع شارة الحالة (قيد الانتظار / مقبول / مرفوض / ملغى) ورقم الحجز لكل موعد
- **إلغاء الحجز**: زر متاح على أي موعد `pending` أو `accepted` بالمواعيد القادمة، يغيّر الحالة لـ `cancelled` — وتلقائياً يرجّع الوقت متاح لمرضى ثانين لو كان الحجز مقبول
- **رقم الجوال إجباري عند تسجيل المريض** (من `login.html`)، ويُحفظ مع كل حجز يسويه

### ميزة التواصل عبر واتساب (لوحة العيادة)
بجدول "طلبات الحجز الجديدة"، كل طلب فيه زر **💬 واتساب** يفتح محادثة مباشرة مع المريض على رقمه، برسالة رسمية جاهزة تلقائياً:

```
السلام عليكم [اسم المريض]،

نفيدكم بخصوص طلب الحجز رقم [رقم الحجز]
📅 التاريخ: [التاريخ]
🕐 الوقت: [الوقت]

نأمل تأكيد الحضور في الموعد المحدد، ولأي استفسار نحن بخدمتكم.

مع تحيات إدارة [اسم العيادة]
```

**رقم الحجز**: مأخوذ من آخر 6 خانات لمعرّف الحجز بقاعدة البيانات (مثال: `A3F9C2`) — رقم مختصر وفريد لكل حجز، يظهر للمريض وللعيادة بنفس المكان.

**ملاحظة تقنية**: رابط واتساب يستخدم صيغة `wa.me/رقم_الدولة+الرقم` (بدون رموز أو مسافات)، فتأكد المرضى يكتبون رقمهم برمز الدولة (مثال: `9665xxxxxxxx`) عشان الرابط يشتغل صح.

## هيكل بيانات Firestore

**مجموعة `users`**: `name`, `email`, `role` (`patient`/`clinic`/`staff`/`admin`), `status`, `createdAt`, `phone` (للمريض والعيادة - إجباري عند التسجيل الذاتي)، `staffOf` (للموظفين بس - uid صاحب حساب العيادة)، وللعيادة تحديداً (اختياري، من تبويب إعدادات العيادة): `logoUrl`, `whatsapp`, `address`, `website`, `instagram`

**مجموعة `doctors`**: `clinicId`, `name`, `specialty`, `workingHours` (مصفوفة `{ date, start, end }` — **تاريخ محدد فعلي، مو يوم أسبوع متكرر**؛ يعني كل مرة تحتاج العيادة تضيف تاريخ جديد لكل فترة دوام)، `createdAt`

**مجموعة `bookings`**: `clinicId`, `doctorId`, `doctorName`, `patientId`, `patientName`, `patientPhone`, `date` (`YYYY-MM-DD`), `time` (`HH:MM`), `status` (`pending`/`accepted`/`rejected`/`cancelled`/`no_show`), `createdAt`

**مجموعة `lockedSlots`**: `doctorId`, `clinicId`, `date` (`YYYY-MM-DD`), `time` (`HH:MM`), `createdAt` — مستند خفيف لكل وقت "مقبول"، بدون أي بيانات شخصية (لا اسم ولا رقم جوال). معرّف المستند نفسه مبني من `doctorId_date_time` عشان يسهل إنشاءه وحذفه بدون قراءة إضافية.

**مجموعة `reviews`**: `bookingId`, `doctorId`, `clinicId`, `patientId`, `rating` (1-5), `comment`, `createdAt` — معرّف المستند نفسه = `bookingId` (يمنع تكرار التقييم لنفس الحجز تلقائياً بدل ما نتحقق يدوياً).

**آلية قفل الوقت (الميزة المميزة)**: لما العيادة تقبل حجز، ينضاف مستند بمجموعة `lockedSlots`. صفحة المريض تولّد كل الأوقات الممكنة من `workingHours` الخاصة بالطبيب **لنفس التاريخ المحدد بالضبط** (كل 20 دقيقة)، وتستثني أي وقت له قفل بـ `lockedSlots` لنفس الطبيب ونفس التاريخ. لما المريض يلغي حجز كان مقبول، ينحذف القفل المطابق تلقائياً ويرجع الوقت متاح.

**ملاحظة توافق**: لو عندك أوقات عمل انضافت قبل هذا التحديث (بنظام يوم أسبوع متكرر)، صفحة المريض لسا تتعرف عليها (توافق عكسي)، بس أي وقت جديد تضيفه العيادة الحين يكون بتاريخ محدد فعلي.

**ليش مجموعة منفصلة بدل قراءة `bookings` مباشرة؟** قواعد الأمان تمنع أي مستخدم من قراءة حجوزات مستخدمين ثانين (فيها اسم ورقم جوال حساس). لو خلينا المريض يتحقق من التوفر بقراءة `bookings` مباشرة، كان لازم نفتح تلك المجموعة للقراءة العامة وتنكشف بيانات كل المرضى. فصلنا "هل الوقت مشغول" (بدون هوية) عن "مين حجزه" (محمي بالكامل).

## نظام التبويبات

كل لوحة (الأدمن، العيادة، المريض) صارت تستخدم **تبويبات فوق** بدل عرض كل الأقسام تحت بعض بالتمرير — يعني تبويب واحد يظهر بمرة، وتبديل التبويب يبدّل المحتوى تحته مباشرة (بدون إعادة تحميل الصفحة). مناسب أكثر لشاشات الجوال الصغيرة.

- **لوحة العيادة**: طلبات الحجز الجديدة | المواعيد المرفوضة | الأطباء | جدول الأسبوع | المواعيد القادمة خلال 24 ساعة | بحث المرضى | الموظفين (لصاحب الحساب الأساسي بس) | الإحصائيات (تظهر لصاحب الحساب وموظفيه) | إعدادات العيادة (لصاحب الحساب الأساسي بس)
- **لوحة الأدمن**: طلبات العيادات | العيادات المرفوضة | الموظفين | آخر التسجيلات | إدارة الحسابات | الإحصائيات الشاملة
- **لوحة المريض**: احجز موعد جديد | مواعيدي الحالية | مواعيدي السابقة

التبويبات قابلة للتمرير أفقياً لو ما كفت الشاشة (خصوصاً بالجوال). الإشعارات (جرس العيادة + التنبيه المنبثق) تبدّل تلقائياً لتبويب "طلبات الحجز الجديدة" عند الضغط عليها حتى لو كنت بتبويب ثاني.

## نظام موظفي العيادات (جديد)

كل عيادة تقدر تضيف موظفين تابعين لها، عندهم نفس صلاحيات العيادة (إدارة الأطباء، الحجوزات، الجدول...) بدون ما يكون عندهم حساب عيادة مستقل.

### كيف يشتغل
- **دور جديد بقاعدة البيانات: `staff`** — منفصل تماماً عن دور `clinic`، عشان ما يتعارض مع أي قوائم عيادات عامة (الشاشة الرئيسية، تصفح المريض) أو قواعد أمان موجودة
- كل حساب موظف مرتبط بحقل `staffOf` (uid صاحب حساب العيادة الأصلي)
- أي بيانات ينشئها أو يعدّلها الموظف (أطباء، حجوزات، جدول...) تُسجَّل تلقائياً باسم **العيادة الأساسية**، مو حسابه الشخصي — يعني الموظف والعيادة يشوفون نفس البيانات بالضبط

### قسم العيادة - تبويب "الموظفين"
- **يظهر بس لصاحب حساب العيادة الأصلي** (الموظف نفسه ما يشوف هذا التبويب، حتى لو دخل)
- نموذج بسيط: اسم، بريد إلكتروني، كلمة مرور → يُنشئ حساب دخول فعّال فوراً (بدون انتظار موافقة أدمن، لأن العيادة نفسها موافق عليها مسبقاً)
- قائمة بكل الموظفين المضافين وحالتهم (فعّال/موقوف) + **🔄 زر Reset** يرسل للموظف رابط إعادة تعيين كلمة المرور مباشرة (بدون حاجة تنتظر الأدمن). الإيقاف والحذف يبقون حصراً بيد الأدمن للأمان

### قسم الأدمن - تبويب "الموظفين"
- يشوف **كل موظفي كل العيادات** بمكان واحد، مع اسم العيادة التابع لها كل موظف
- ✏️ **تعديل** (الاسم والبريد)
- ✅/⛔ **تفعيل/إيقاف**
- 🔄 **إعادة تعيين كلمة المرور**: متاح بتبويب "الموظفين" وبجدول "إدارة الحسابات" العام (مريض/عيادة) — يرسل بريد رسمي من Firebase فيه رابط آمن لصاحب الحساب يغيّر كلمة مروره بنفسه — **محدش يقدر يشوف كلمة المرور الفعلية أبداً، حتى الأدمن**، لأن Firebase Authentication ما يخزّن كلمات المرور بصيغة يقدر أحد يستردها (حتى بصلاحيات كاملة) — هذا معيار أمان أساسي وما نقدر (ولا يصح) نتجاوزه
- 🗑️ حذف

### ملاحظة تقنية (Secondary Firebase App)
إنشاء حساب دخول جديد بينما أنت مسجّل دخول بحساب ثاني (العيادة تنشئ حساب الموظف) له مشكلة تقنية معروفة بـ Firebase: العملية تسجّل خروجك تلقائياً وتسجّل دخول بالحساب الجديد! لحل هذا، نستخدم **تطبيق Firebase ثانوي منعزل** (Secondary App Instance) بس لعملية الإنشاء، فتبقى جلسة العيادة الأساسية شغّالة بدون تأثير.

## ميزات جديدة: التذكير، لم يحضر، الإحصائيات، التصدير

### 🔔 تذكير واتساب يدوي
كل موعد بجدول الأسبوع فيه زر **🔔 تذكير** منفصل عن زر "واتساب" الأصلي — يفتح رسالة جاهزة مختلفة (صيغة تذكير بالموعد، مو تأكيد حجز). العيادة تضغطه صباحاً لمواعيد اليوم/بكرة.

**ليش مو تلقائي بالكامل؟** التطبيق حالياً موقع ثابت (GitHub Pages) بدون خادم خلفي شغّال باستمرار (Cloud Functions/Cron Job) يقدر يرسل رسائل من نفسه بدون أي نشاط من حد. الإرسال التلقائي الحقيقي (بدون ضغط زر) يحتاج ترقية البنية التحتية لاحقاً (Firebase Cloud Functions + جدولة زمنية)، وهذا ممكن نضيفه بمرحلة قادمة لو احتجته.

### ❌ علامة "لم يحضر" (No-show)
منفصلة تماماً عن "مرفوض" — تظهر بزر بجدول الأسبوع بس على المواعيد المؤكدة اللي تاريخها اليوم أو فات. مفيدة لتتبع المرضى اللي يغيبون كثير عبر الإحصائيات.

### 📊 تبويب "الإحصائيات" (جديد بلوحة العيادة)
- 4 بطاقات ملخص: إجمالي الحجوزات، أكثر طبيب مطلوب، أكثر وقت ازدحاماً، نسبة الإلغاء/الرفض/الغياب
- 3 رسوم بيانية (Chart.js عبر CDN): الحجوزات حسب الطبيب، الحجوزات حسب الساعة، مرضى جدد شهرياً (آخر 6 أشهر)
- كل الحسابات تتم محلياً بالمتصفح من البيانات المحمّلة أصلاً (بدون استعلامات إضافية لقاعدة البيانات)

### 📥 تصدير Excel/CSV
زر بتبويب الإحصائيات يصدّر **كل حجوزات العيادة** (رقم الحجز، المريض، الجوال، الطبيب، التاريخ، الوقت، الحالة) كملف CSV يفتح مباشرة بـ Excel (مع دعم كامل للحروف العربية).

## إضافة "موعد" كتطبيق على الشاشة الرئيسية (Add to Home Screen)

التطبيق مجهّز الآن يبان كتطبيق حقيقي (أيقونة + بدون شريط متصفح) لما أي حد يضيفه لشاشته الرئيسية، سواء أندرويد أو آيفون.

### الملفات المضافة
- `manifest.json` (بالجذر): يعرّف اسم التطبيق، الأيقونة، ولون الواجهة لمتصفحات أندرويد/كروم
- `assets/icons/`: أيقونات بأحجام مختلفة (512، 192، 180، 152، 32 بكسل) مقصوصة من الشعار نفسه

### كيف يستخدمها الزوار
**أندرويد (كروم)**: يفتح الموقع → قائمة المتصفح (⋮) → **"إضافة إلى الشاشة الرئيسية"** أو **"تثبيت التطبيق"**
**آيفون (سفاري)**: يفتح الموقع → زر المشاركة (□↑) → **"إضافة إلى الشاشة الرئيسية"**

بعدها تطلع أيقونة "موعد" بشعارها الحقيقي، وفتحها يشغّل التطبيق بدون شريط عنوان المتصفح (وضع Standalone) — نفس تجربة أي تطبيق مثبّت عادي.

**ملاحظة**: هذا "PWA خفيف" (بدون عمل بدون إنترنت Offline) — يحتاج اتصال إنترنت يشتغل زي ما هو الحال بالموقع العادي، بس شكله وسلوكه يبان كتطبيق مستقل.

## أربع ميزات جديدة: الجملة، التقييم، إعادة الجدولة، والإحصائيات الشاملة

### 📅 إضافة أوقات عمل بالجملة (لوحة العيادة)
بدل إضافة كل تاريخ لطبيب لحاله، زر **"📅 إضافة بالجملة"** بجانب النموذج العادي — تحدد نطاق تاريخ (من - إلى) + أيام الأسبوع اللي تبيها (مثلاً كل أحد وثلاثاء) + وقت البداية والنهاية، وتتولّد كل التواريخ المطابقة تلقائياً بضغطة وحدة (بحد أقصى 6 أشهر بالمرة، ويتجاهل أي تاريخ مكرر موجود مسبقاً).

### ⭐ تقييم المريض للطبيب بعد الزيارة
- بقسم "مواعيدي السابقة"، أي موعد **مقبول ومكتمل** فيه زر "⭐ قيّم زيارتك" (يختفي بعد أول تقييم)
- نجوم (1-5) + تعليق اختياري
- متوسط تقييم كل طبيب يظهر للمريض بخطوة اختيار الطبيب (يساعده يقرر)
- مجموعة `reviews` جديدة، بمعرّف مستند = رقم الحجز نفسه (يمنع تكرار التقييم لنفس الزيارة تلقائياً)
- **تذكير تلقائي (Popup) مرة وحدة بكل جلسة دخول**: أول ما يفتح المريض التطبيق، لو عنده زيارة مكتملة ما قيّمها بعد، تطلع له نافذة تقييم مباشرة (أحدث زيارة غير مقيّمة)، مع خيار "لاحقاً" لو مو بذاك الوقت

### 🔁 إعادة جدولة الموعد (مو بس إلغاء)
زر "🔁 إعادة جدولة" بجانب "إلغاء الحجز" لأي موعد قادم (قيد الانتظار أو مقبول) — يلغي الحجز الحالي (ويحرر الوقت لو كان مقبول) ويوديك مباشرة لخطوة اختيار وقت جديد لنفس الطبيب، بدل ما تبدأ من الصفر.

### 📊 الإحصائيات الشاملة (تبويب جديد بلوحة الأدمن)
نظرة عامة على **المنصة كلها** (كل العيادات مع بعض)، منفصلة عن إحصائيات كل عيادة لحالها:
- بطاقات: عيادات فعّالة، إجمالي الأطباء، إجمالي المرضى، إجمالي الحجوزات، نسبة الإلغاء/الرفض/الغياب
- رسم بياني: تسجيلات جديدة شهرياً (عيادات + مرضى، آخر 6 أشهر)
- رسم بياني: أكثر 5 عيادات نشاطاً حسب عدد الحجوزات

## 🏖️ تعطيل يوم كامل للطبيب بضغطة وحدة (لوحة العيادة)
بجانب نموذج إضافة الأوقات، صف بسيط: تختار تاريخ + زر **"🏖️ تعطيل هذا اليوم"** — يحذف **كل** أوقات عمل الطبيب المسجّلة بذاك التاريخ دفعة وحدة (بدل ما تحذفها وحدة وحدة يدوياً). مفيد لإجازة الطبيب المفاجئة.

**ملاحظة**: التطبيق عربي بالكامل حالياً (بدون خيار لغة إنجليزية) — إذا احتجنا دعم لغة ثانية مستقبلاً نقدر نضيفه.

## صور الأطباء + شعارات العيادات + دليل بقسمين متمرّرين

### ⚠️ Firebase Storage رجعت (خطوة إجبارية)
هذي الميزة تحتاج **Firebase Storage** — نفس الخدمة اللي استخدمناها قبل بميزة الإعلانات وألغيناها. الحين نحتاجها من جديد لأنها ميزة أساسية أكثر:

1. Firebase Console → **Storage** → **Get started** (لو ما كانت مفعّلة أصلاً)
2. تبويب **Rules** بنفس صفحة Storage → امسح الموجود → الصق محتوى `storage.rules` المرفق → **Publish**

### قسم العيادة - رفع صورة الطبيب
بوضع تعديل أي طبيب (تبويب الأطباء)، فيه حقل رفع صورة اختياري (حد أقصى 3 ميجابايت) بجانب الاسم والتخصص — تُحفظ وتظهر كأفتار مصغّر برأس الطبيب بالقائمة.

### قسم العيادة - تبويب "إعدادات العيادة"
تبويب مخصص لصاحب الحساب الأساسي بس (ما يظهر للموظفين — القاعدة الأمنية موجودة أصلاً بقاعدة `users` فما احتجنا تعديل عليها):
- رفع شعار العيادة (حد أقصى 3 ميجابايت)، يظهر فوراً بمعاينة
- **بيانات تواصل كاملة**: رقم واتساب العيادة، الموقع/العنوان، الموقع الإلكتروني، وحساب انستقرام — كلها تُحفظ بحقل واحد بحساب العيادة (`whatsapp`, `address`, `website`, `instagram`)

### الشاشة الرئيسية - دليل بقسمين منفصلين قابلين للتمرير
بدل شبكة عيادات واحدة، صار فيه قسمين مستقلين تحت شريط البحث والتخصصات:
- **"الأطباء"**: كروت تمرير أفقي (يمين-يسار) لكل طبيب — صورته الحقيقية (أو أفتار بأول حرف من اسمه لو ما رفع صورة)، اسمه، تخصصه، واسم عيادته
- **"العيادات"**: كروت تمرير أفقي مشابهة — شعار العيادة الحقيقي (أو أفتار ملوّن لو ما رفعت شعار)، اسمها، تخصصاتها، **الموقع/العنوان بخط صغير جداً**، وصف أيقونات تواصل قابلة للضغط (💬 واتساب يفتح محادثة مباشرة، 🌐 الموقع الإلكتروني، 📷 انستقرام) — تظهر بس لو العيادة عبّت البيانات. **عنوان هذا القسم بخط أصغر من "الأطباء"** حسب الطلب

فلتر التخصص ومربع البحث يشتغلون على **القسمين مع بعض بنفس الوقت** — تختار تخصص أو تكتب كلمة، وينفلتر الأطباء والعيادات مع بعض تلقائياً.

## قواعد أمان Firestore (Security Rules)

ملف `firestore.rules` يحدد بالضبط مين يقدر يقرأ ويكتب كل مجموعة بيانات:

| المجموعة | القاعدة العامة |
|---|---|
| `users` | أي زائر (حتى بدون تسجيل دخول) يقرأ بيانات العيادات الفعّالة بس (للشاشة الرئيسية). كل مستخدم يقرأ بياناته هو، الأدمن يقرأ الكل، والعيادة تقرأ بيانات موظفيها هي بس. التسجيل الذاتي بحساب المستخدم نفسه فقط (ما يقدر يسجل نفسه أدمن أو موظف)، ورقم الجوال إجباري. العيادة الأساسية (مو موظف) تقدر تنشئ حساب موظف تابع لها فعّال مباشرة. الأدمن بس يوافق/يوقف/يحذف حساب. |
| `doctors` | قراءة عامة حتى بدون تسجيل دخول (اسم وتخصص الطبيب معلومة عامة، تحتاجها الشاشة الرئيسية للتصفح). الإضافة/التعديل/الحذف للعيادة المالكة أو أحد موظفيها الفعّالين. |
| `bookings` | المريض يشوف حجوزاته، العيادة وموظفيها يشوفون حجوزات العيادة، الأدمن يشوف الكل. الإنشاء لمريض فعّال بس وبحالة `pending` دايماً. العيادة أو موظفوها يقدرون يقبلون/يرفضون/يعدّلون (التاريخ، الوقت، اسم ورقم جوال المريض)، والمريض صاحب الحجز يقدر يلغيه (`cancelled`). |
| `lockedSlots` | أي مستخدم مسجّل دخول يقرأ (بيانات غير حساسة: طبيب + تاريخ + وقت بس). الإنشاء للعيادة أو أحد موظفيها، والحذف مفتوح لأي مستخدم فعّال (آمن لأنه ما فيه بيانات شخصية). |
| `reviews` | قراءة عامة. الإنشاء لمريض فعّال على حجزه هو بس، وبشرط الحجز يكون مقبول فعلاً (تحقق مباشر من مستند الحجز). التعديل للمريض صاحب التقييم بس. الحذف للأدمن بس. |

### كيف تطبّقها
1. روح لـ **Firebase Console** → **Firestore Database** → تبويب **Rules**
2. امسح المحتوى الموجود والصق محتوى `firestore.rules` كامل
3. اضغط **Publish**

⚠️ **قبل ما تنشرها، جرب التطبيق بكامل تدفقاته** (تسجيل عيادة، موافقة أدمن، إضافة طبيب، حجز مريض، قبول/رفض) **وأنت لسا بوضع Test mode**، عشان تتأكد كل شي يشتغل صح قبل ما نطبّق القيود. لو صار أي خطأ "Missing or insufficient permissions" بعد التفعيل، رجعلي وبنعدلها.

**ملاحظة تقنية مهمة لأي تطوير مستقبلي**: Firestore يرفض أي استعلام (query) لو فيه احتمال إنه يرجّع مستند ما يحقق شرط القاعدة — حتى لو بعدين بتفلتر النتائج بنفسك بالجافاسكريبت. يعني `.get()` من غير `.where()` على مجموعة محمية (زي `users` أو `bookings`) بيفشل لأي حد مو أدمن. لازم دايماً تحدد شرط `.where()` يطابق بالضبط شرط القاعدة (`role == 'clinic'`, `patientId == uid`, إلخ) عشان الاستعلام يشتغل.


لا يوجد تسجيل أدمن من الواجهة (مقصود لأسباب أمان). يُنشأ يدوياً:
1. Firebase Console → Authentication → Add user (بريد + كلمة مرور)
2. انسخ الـ UID
3. Firestore → مجموعة `users` → مستند جديد بنفس الـ UID، بالحقول: `name`, `email`, `role: "admin"`, `status: "active"`, `createdAt`

## قبل التجربة - إعدادات مطلوبة على Firebase Console
1. **Authentication** → Sign-in method → تفعيل Email/Password
2. **Firestore Database** → إنشاء قاعدة بيانات (Test mode مؤقتاً)

## تدفق تجربة كاملة (End-to-End)
1. سجّل حساب عيادة من `login.html` → بيصير `pending`
2. سجّل دخول كأدمن → وافق على العيادة من لوحة الأدمن
3. سجّل دخول بحساب العيادة → أضف طبيب وحدد أوقات عمله
4. سجّل حساب مريض جديد → احجز موعد مع ذلك الطبيب
5. رجّع لحساب العيادة → بتلاقي طلب الحجز بانتظار القبول/الرفض
6. اقبل الطلب → رجّع لحساب المريض وشوف حالة الموعد صارت "مقبول"، وجرّب تحجز نفس الوقت بحساب مريض ثاني — بتلاحظ إنه اختفى من الأوقات المتاحة
